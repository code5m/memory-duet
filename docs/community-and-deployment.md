# Memory Duet 社区与部署实施手册

## 一、免密码游客身份

- 游客只需输入任意非空昵称（最多 30 字），没有密码、手机号、邮箱。
- 创建时生成独立的 `guest_id` 与随机会话 token；token 的 SHA-256 摘要保存在服务器 SQLite，原始 token 仅返回客户端并存入其浏览器本地存储。
- 相同昵称可以重复，不表示本人身份；清除浏览器数据后不能凭昵称恢复会话。
- token 过期后需新建游客；不要在聊天里发送 token。
- 读取公共瓶子无需昵称；发瓶、回信、点赞收藏、关注、私信、共学等写操作要求当前游客 token。

## 二、两种漂流瓶

| 类型 | 发起动机 | 内容 | 互动与结果 |
| --- | --- | --- | --- |
| **太难记漂流瓶**（hard） | 有难点需要搭子帮助 | 标题、难点、学科、可选方法 / 标签 / 图片 | 接瓶、建议记法、瓶主精选回信 |
| **记忆秘诀瓶**（secret） | 分享验证过或正在试验的方法 | 知识背景、秘诀步骤、适用场景、核对方式 | 查看、尝试、评论、收藏、点赞 |

两种瓶子都不应假称一条秘诀适用于所有人。只披露愿意公开的材料和照片。

## 三、共学练习室

创建者填写题目、学习提示和参考答案；题干不应暴露答案。游客加入一间房（最多 8 人）后，可以选择显示提示或直接作答。答案由服务端进行精确文本归一化匹配，结果分为独立正确、提示后正确、未答对。

同一房间每位游客只能提交一轮；这避免在一轮内反复猜测刷“独立正确”。平台无法保证用户没有借助其他设备或网络，因此提示使用属于用户自报，不能宣称监考或真实记忆力认证。

## 四、上线部署

最简单：`python3 server.py` 在本机启动，只可从当前机器访问。

部署在共享服务器时，必须有 HTTPS 反向代理，示例：

```bash
export MEMORY_DUET_HOST=127.0.0.1
export MEMORY_DUET_PORT=8765
export MEMORY_DUET_ADMIN_TOKEN='请生成一个长期安全的管理口令'
python3 server.py
```

由 Nginx、Caddy 或其他反向代理将公开的 HTTPS 域名转发给 localhost:8765。不要将带 token 的调试日志公开。保持 `data/` 持久化并定期备份，推荐每次部署之前保存 `community.sqlite3` 一致性快照。

也可以使用仓库的 `Dockerfile` / `compose.yaml`，仅将 8765 映射到服务器本机回环地址，再由 TLS 反向代理公开访问。

### 小程序

- 在微信公众平台申请自己的正式 AppID。
- 在 `miniapp/config.js` 填写 `https://your-domain.example` 等真实部署域名。
- 添加微信小程序 request 合法域名，遵守微信开放平台有关个人信息和用户生成内容的要求。
- 在微信开发者工具逐页检查，经过真机兼容性与审核之后才能对外发布。

## 五、运营与治理

- `GET /api/community/admin/reports` 需 HTTP 头 `X-Admin-Token` 为 `MEMORY_DUET_ADMIN_TOKEN` 配置的值。
- `POST /api/community/moderate` 接收 JSON `{"type":"bottle"|"reply"|"room","id":"记录 ID","action":"hidden"|"visible"}`，同样需要管理员 token。
- 举报由不同游客提交；3 个不同游客举报后自动临时隐藏帖子、回信或共学室，需要人工复核是否恢复。游客身份可自由创建，因此这个阈值容易遭到滥用；正式开放前必须增设人工审核、反刷与申诉。
- API 已限制单 IP 操作频率及请求体大小，但这不是综合安全网关。正式上线应增加 Abuse 监控、日志脱敏、备份恢复、滥用封禁、合规隐私政策、删除与导出申请流程。

## 六、验收要点

1. 用两个不同浏览器填写相同昵称，应该创建不同游客身份。
2. A 发布太难记漂流瓶；B 回答，A 精选；B 再发布记忆秘诀瓶，A 收藏。
3. A、B 互相关注后才可私信，任一方屏蔽后停止新消息。
4. A 创建共学题，B 进入并无提示答题，A 看提示后答题，两种结果明确区分。
5. 第三名游客可以举报不合适的内容；3 位不同游客举报后隐藏，管理员可审核恢复。
6. PC / 平板 / 手机、微信小程序验证页面布局；不把小程序静态源码当作真机验收结果。

## 七、预留开发

目前浏览器端独立学习档案与服务端社交身份分离，尚未支持跨端登录同步。后续如需跨端同步，应明确用户同意、设计安全的身份恢复及隐私保护机制，不应将“随便输入同一昵称”误认为可信身份。
